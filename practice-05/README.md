# Практическая работа № 5

Асинхронные операции и получение данных с сервера.

**Автор** — Узеев Руслан, ЭФБО-05-25, вариант 5. Окружение — Node.js 24.16.0, npm 11.13.0, Git 2.50.1.

## Запуск

Из корня проекта запустить сервер в первом терминале:

```bash
npm --prefix practice-05 start
```

Во втором терминале выполнить:

```bash
npm --prefix practice-05 run client
npm --prefix practice-05 run client -- --demo
npm --prefix practice-05 test
```

Адрес API — http://127.0.0.1:5505/api. Для другого порта передать адрес через `API_URL`. Зависимости устанавливать не требуется.

## Очереди выполнения

| Команда из practice-05 | Прогноз по коду | Фактический порядок |
| --- | --- | --- |
| `npm run example:order` | A B C D E F | A B C D E F |
| `npm run example:order -- --extra` | A B C D E G F | A B C D E G F |

A, B и C выполняются в текущем стеке. После его освобождения микрозадачи D и E выполняются в порядке постановки. Дополнительная микрозадача G встаёт после них. Обработчик таймера F запускается после микрозадач.

## HTTP и устройство клиента

| Запрос | Статус | Content-Type и результат |
| --- | ---: | --- |
| `/health` | 200 | JSON, статус API |
| `/tasks?completed=false&priority=high` | 200 | JSON, отфильтрованный список |
| `/categories` | 200 | JSON, категории |
| `/tasks/999` | 404 | JSON, `TASK_NOT_FOUND` |
| `/debug/error` | 503 | JSON, `SERVICE_UNAVAILABLE` |
| `/debug/text` | 200 | `text/plain`, клиент отклоняет ответ |
| `/debug/invalid-json` | 200 | JSON по заголовку, ошибка при разборе тела |

`api-client.js` собирает URL, сохраняет `false` и `0`, добавляет `Accept` и объединяет тайм-аут с сигналом вызывающего кода. Сначала проверяется `response.ok`, затем статус 204, тип содержимого и JSON. `task-api.js` задаёт маршруты, нормализует фильтры и проверяет схему, уникальность id и `meta.total`. `variant.js` хранит параметры варианта. `main.js` запускает сценарий и отдельно показывает диагностический ответ 404.

| Вид ошибки | Причина |
| --- | --- |
| `http` | Получен неуспешный статус. Сохраняются статус, URL, код и детали при наличии. |
| `network` | Запрос завершился без HTTP-ответа. |
| `invalid-response` | Неверный тип ответа, JSON или предметная схема. |
| `timeout` | Сработал тайм-аут клиента. |
| `aborted` | Запрос отменён внешним сигналом. |

Независимые задачи и категории загружаются с `Promise.all`. Для двух запросов к `/debug/delay?ms=150` три последовательно выполненных замера дали 326,7 / 307,3 / 309,9 мс, а параллельные — 155,2 / 154,9 / 154,1 мс.

## Контрольный и индивидуальный сценарии

| Запрос | Ожидаемые id | Фактические id | Фактический total |
| --- | --- | --- | ---: |
| `GET /api/tasks?completed=false&priority=high` | 4, 13, 34 | 4, 13, 34 | 3 |
| `GET /api/tasks?categoryId=1` | 1, 7, 13 | 1, 7, 13 | 3 |

`categoryId=1` выбирает все задачи категории «Учёба». В обоих режимах отдельно получен `404 TASK_NOT_FOUND` для id 999. Запуск с адресом неслушающего порта вернул `network`. Повтор с рабочим адресом успешно загрузил данные.

## Проверки

| Набор | Ожидалось | Пройдено | Ошибок |
| --- | ---: | ---: | ---: |
| API | 18 | 18 | 0 |
| Клиент | 26 | 26 | 0 |
| Интеграция | 13 | 13 | 0 |
| Собственные | 3 | 3 | 0 |

В собственных проверках покрыты сочетание фильтра варианта с `completed=false`, HTTP 429 с повреждённым JSON и отмена до вызова `fetch`. Интеграционные проверки подтверждают отдельную классификацию тайм-аута и внешней отмены на реальном локальном API.

Модуль HTTP-запросов и предметный клиент можно использовать независимо от интерфейса. Параллельная загрузка сокращает ожидание независимых ресурсов, а ошибки сохраняют сведения, необходимые для диагностики.
